## A. 阻塞性歧义（必须先拍板）

### A1 「攻击2 / 攻击3 / 攻击8 / 攻击20」是伤害值还是攻击次数？

设计稿在这里用了两种写法，读法完全不同：

| 写在哪 | 字面 | 两种读法 | 强度差 |
|---|---|---|---|
| 地精·近战 | `攻击2` | ① `SingleAttackIntent(2)` 打 2 点 ② `MultiAttackIntent(?, 2)` 打两次 | 完全不同的量级 |
| 地精·远程 | `攻击3` | 同上 | 同上 |
| 明萨拉 | `攻击8` / `攻击20` | 同上 | 同上 |

- 若按①：地精 40 血、每次只打 2–3 点，配 5 只怪 → **这场战斗会拖得非常长**（玩家第一层通常 15–25 血上限区间的伤害承受能力，2 点/回合挠痒）；
- 若按②：地精每次打两次，叠加 5 只怪的意图数 → 又可能过载。

**必须逐条写明 `伤害值 × 段数`**，例如 `攻击2` → 「造成 2 点伤害，1 次」。原版代码里这是两个不同的类：`SingleAttackIntent(dmg)` 与 `MultiAttackIntent(dmg, times)`。

> 顺带（**2026-10-01 修订**）：第一幕精英共 **6 场** —— Overgrowth 的 `BygoneEffigyElite`(1 只) / `ByrdonisElite`(1 只) / `PhrogParasiteElite`(**5 只**：本体 + `InfestedPower` 召唤 4 只 Wriggler)，Underdocks 的 `PhantasmalGardenersElite`(**4 只**) / `SkulkingColonyElite`(1 只) / `TerrorEelElite`(1 只)。初稿写的"三场都是单怪"**是错的**，`PhrogParasiteElite` 开场 1 只、本体死后变 5 只。
> 血量基准：`Byrdonis 81–84`、`BygoneEffigy 127–132`、`PhrogParasite 61–68`。本设计总血量 150+40+30+5+5 = **230**。与单怪精英比是 1.7–2.8 倍，但**与 4–5 只怪的 `PhantasmalGardenersElite` / `PhrogParasiteElite` 属于同一量级**，因此并非离群 —— 真正的强度问题在伤害节奏（见 4.4 的 59 点），不在血量总量。

### A2 「眩晕」在三个怪身上是三件事

设计稿第 15 行只写了一句总则「所有怪物的意图状态机若被眩晕等状态打断，则顺延一回合」，然后三只怪都出现了「眩晕」，但含义显然不同：

| 出处 | 大概率含义 | 需要澄清的点 |
|---|---|---|
| 地精·远程 `攻击2 - 眩晕 - 强化` | **它自己眩晕**（一回合不做事，像"装填/瞄准"） | 还是想让**玩家**眩晕？ |
| 油桶 `while(true){眩晕}` | 它自己永远不做事 | 与"没有手脚"的备注一致，但要不要给它一个"待机"的视觉表现？ |
| 地精·近战 / 明萨拉 | 出现在总则里 | 它们自己不会眩晕，这里指的是"**被玩家眩晕时**的顺延规则" |

**关键**：塔 2 里"怪物眩晕自己"和"眩晕玩家"是两套完全不同的东西——
- 怪物自己眩晕 = `StunIntent`，它这回合什么都不做；
- 玩家被眩晕 = 是挂在玩家身上的 debuff（原版只有 `AsleepPower` 一类，语义是"跳过"），跟你写的地精循环没有关系。

**必须在 D2 里对每只怪逐行标注：`眩晕` = 自己不动 / 让玩家不动。**

另外，总则里的「顺延一回合」与原版默认行为**不等价**（见制作清单 2.3）：
`CreatureCmd.Stun(creature, nextMoveId)` 缺省 `nextMoveId` = **重复上一次已执行的行动**，而你写的是「执行本该这回合执行的那一招」。两者在第 3、4 回合会岔开。设计稿必须显式写明"打断后接哪一招"，代码里传显式 `nextMoveId`。

### A3 明萨拉状态机的 `break` 语义与第二阶段衔接

原文：

```
while(true) {
    for i in range(2) { 守护灵光; 勇气灵光; 攻击8; 强化+2力量; }
    攻击20;
    if (同场战斗中的两个地精队友都死了)  break; //这个判定不占用回合
}
while (true) { 攻击20; 强化+1力量; }
```

四个问题：

1. **`break` 之后从哪一招接上？** 第一阶段的最后一招是 `攻击20`，第二阶段第一招也是 `攻击20` → 队友死亡时会**连打两个 20**。这是设计意图吗？
2. **判定时机到底是什么时候？** "不占用回合"只说了它不是一个动作，没说它挂在哪儿。可选：本轮招式执行后 / 下回合开始前 / 每次有队友死亡时立即。三种实现的节奏完全不同。
3. **队友在明萨拉出手前就死了怎么办？** 本轮她打第一阶段的 `攻击8` 还是第二阶段的 `攻击20`？
4. **「两个地精队友」是否包含油桶？** 字面是"两个地精"，但油桶也是同场敌人。判定必须显式写成 `CombatState.Enemies` 里**地精·近战 与 地精·远程 都阵亡**（原版有现成写法可抄：`RampartPower.cs:27` 用 `CombatState.Enemies.Where(c => c.Monster is TurretOperator)` 判特定队友存活）。

> 这段 `for in range(2)` + `while(true)` + `break` 的写法本身也不适合直接落成状态机。原版的工具是 `MoveState.FollowUpState`（线性链）+ `ConditionalBranchState`（条件分支）。建议在设计稿里改画成**招式序列 + 一个条件出口**，而不是伪代码。

### A4 油桶「死亡引爆」的作用域与连锁

原文：「被卡牌"拾取"以外的方式击败时，对所有玩家造成10点伤害，对所有敌人造成其最大生命值1/3的伤害。」

四个必须钉死的点：

1. **两个油桶会不会互相引爆无限循环？** 场上有 **2** 个油桶。打死 A → 对 B 造成 `5/3`（向下取整 = 1 点）→ B 如果因此死亡，会不会再触发一次引爆、又打回 A？A 已经死了。但如果设计里存在 3 个以上油桶或以后加了会互相伤害的怪，**这就是一个能递归到崩栈/死循环的设计**。建议明确写：**同一次引爆链中每个油桶只触发一次**（或干脆规定引爆伤害不致死其他油桶）。
2. **"所有敌人"包不包括油桶自己 / 其他油桶？** 从玩家视角，明萨拉、地精、油桶都是"敌人"。
3. **伤害有没有来源、吃不吃增益？** 原版 `ExplosiveAmpoule` 用的是 `ValueProp.Unpowered`（无来源，不受力量/易伤/虚弱影响）。引爆伤害用哪一档？10 点是不是也走 Unpowered？
4. **联机多人时"对所有玩家造成10点"是每人 10 点还是共 10 点？** 多人模式下这是完全不同的强度。

另外：「被卡牌拾取以外的方式击败」需要**死亡来源判定**，但原版的死亡钩子**不带来源参数**（`Hook.BeforeDeath(runState, combatState, creature)` / `AfterDeath(..., creature, ...)` 只有 `creature`）。所以代码上只能在拾取卡里自己打标记（挂隐藏 power / 维护集合）。设计稿应当把这条写成"**实现约定**"而不是"效果描述"，否则实现时会走弯路。

## C. 明萨拉的两个灵光（缺关键定义）

原文：

```
守护灵光：每回合获得5点格挡，持续2回合
勇气灵光：每回合获得1点活力，持续2回合。
两个灵光均为对全体队友（即玩家的敌人）生效
```

先说好消息：**「活力」在原版是真实存在的** —— `VigorPower`（`Core/Models/Powers/VigorPower.cs`，语义是"下一次有来源攻击额外加伤"）。所以勇气灵光可以直接用原版 power 实现，不用自造。

但下面这些必须补：

| 问题 | 为什么必须定 |
|---|---|
| **包不包括明萨拉自己？** | "对全体队友生效"——她自己算不算队友？如果算，她的 4 条循环里会给自己叠 2 次灵光 |
| **"持续2回合"从哪一刻算起？** | 施加当回合算 1 回合，还是从下一回合开始算？两者相差整整一回合的收益 |
| **可否叠加？** | 第一阶段循环两轮会放 **2 次** 灵光。第二次是刷新持续时间、叠加数值、还是完全无效？原版 power 有 `Counter` 层数机制，这两种处理结果差异巨大 |
| **"每回合获得"的触发时机** | 敌人回合开始时 / 每个队友自己的回合开始时？原版可挂在 `Hook.AfterSideTurnStart` / `Hook.AfterPlayerTurnStart`，选哪个要定 |
| **power 的图标与显示** | 需要 64×64 与 256×256 两套图；是否显示在血条下方 |
| **可否被驱散 / 是否受"能力层数修改"影响** | 有卡牌会改 power 层数，需要明确 |
| **明萨拉死了灵光还在吗** | 若灵光挂在队友身上、明萨拉死亡，是否立即清除 |

另外「强化：守护灵光 / 勇气灵光」这两个是**意图**（她花一回合上 buff），但设计稿没写这两个意图在界面上怎么显示——原版对上 buff 的意图用 `BuffIntent`（一个向上箭头的通用图标）。如果要做成有辨识度的专属图标，那是额外的美术需求（**这是唯一一处可能需要新画意图图标的地方**）。

## D. 遭遇配置（缺）

| 缺什么 | 说明 |
|---|---|
| **具体是哪一个第一幕** | 「第一层」有两个幕：`Overgrowth` 与 `Underdocks`，**两者 `Index` 都是 0**。设计稿需要明确是"只出在 Overgrowth"还是"两个第一幕都出" |
| `RoomType` / `IsWeak` 落字段 | 从"精英级"可推断 `RoomType.Elite` + `IsWeak=false`，但需要显式写成字段 |
| **`Tags`** | 决定"相邻两场战斗不会同类"。复用哪个原版 tag（如 `Workers`？）还是留空不受约束 |
| **槽位名与站位坐标** | 5 只怪必须有专属战斗场景（`scenes/encounters/<名>.tscn`），槽位名要与代码 `Slots` 一致。设计稿的"排列"只给了顺序，没给左右位置与坐标 |
| **镜头缩放 / 偏移** | 5 只怪偏宽，原版 4 怪精英用了 `GetCameraScaling()=0.85` + `GetCameraOffset()=Vector2.Down*40`。本场需要类似参数 |
| **`HpBarSizeReduction`** | 5 只怪血条会挤，可能需要给矮的油桶压缩血条 |
| **BGM / 环境音** | 精英战是否用第一幕精英音乐（默认）还是专属 |
| **`catch=true` 的技术定义** | 这是设计稿自造的概念，引擎里没有"战斗参数"这种字段。需要约定实现方式（建议：遭遇子类上的布尔属性，或按遭遇 Id 白名单判定），并在设计稿里写清楚 |
| **遭遇标题 / 战败文案** | `encounters.json` 的 `title` 与 `loss` 都是必填，缺了会在战败界面显示裸 key |
| **期望出现频率** | 原版精英池每场权重硬编码为 1.0，加入后就是等概率稀释。需要确认"等概率"可接受，还是要打补丁做权重 |
| 内部英文名 | 决定类名、本地化键名、资源路径（如 `MINTHARA_ELITE`） |

## E. 拾取卡（缺关键口径）

设计稿写的效果很完整，但有一处**内部矛盾**和若干实现口径缺失：

### ⚠️ E1 「无色牌」与「只在本 mod 战斗中才有」互相冲突

原版的牌只有两条路：**进卡池**（可被抽到、可在奖励中出现、可被商店卖），或者**战斗内临时生成**（不进池）。设计稿说的是后者，但用了"无色牌"这个池概念。

必须明确：
- 它**不进任何卡池**（否则会污染原版卡池 / 出现在卡牌奖励里）；
- 它是"战斗内生成物"，原型仍然是一个 `CardModel`；
- **所有角色都能用**（包括 Denia 等 mod 角色）——"无色"暗示了这点，要写实。

### E2 其余实现口径

| 缺什么 | 说明 |
|---|---|
| 塞牌的确切时机 | "每个回合开始时的抽牌完成后" → 对应 `Hook.AfterHandDraw`（在 `BeforeHandDraw` 之后）。但要确认是**每个玩家**的回合开始，还是只有单人模式 |
| 手牌满了怎么办 | 手牌有上限（原版 10）。超过时是塞不进去、还是塞了挤掉一张？（这是本 mod 唯一会"每回合自动生成卡牌"的机制，容易出边界问题） |
| 运气不佳时的手感 | 每回合保底一张 + 消耗 + 虚无，意味着只要场上还有油桶，玩家每回合都在"用一张牌换一瓶药水"。要不要设上限（如最多生成 N 张）？ |
| 对无效目标使用 | "没有任何效果"——那**还强制结束回合吗？还消耗能量吗？还消耗这张牌吗？** 三个都要写 |
| 强制结束回合的时机 | 只在该敌人**被成功拾取**时，还是只要打出这张牌就结束？ |
| 拾取是否算"击杀" | 是否给金币奖励？（替换比例走 `EncounterModel.CalculateGoldProportion`）是否触发"击杀时"类效果？ |
| 拾取是否绕过死亡防止 | 原版 `CreatureCmd.Kill(creature, force)` 有 `force` 参数（`force:false` 时会被"死亡防止"类效果挡下）。拾取要不要 `force:true`？ |
| 目标合法性 | 只能选带"可被拾取"的敌人，还是任何敌人都能选（选了没效果）？交互上差别很大 |
| 拾取产出的**通用映射表** | 设计稿只写了油桶 → 爆炸药水。目前只有油桶有"可被拾取" power，所以这条暂时够用；但一旦加第二个可拾取怪，就需要 D7 映射表 |

### 💡 顺手补上你标注的 TODO

设计稿第 59 行「被拾取后变成一个原版游戏的aoe爆炸药水 #具体名称我忘了」——

就是 **爆炸安瓿（`ExplosiveAmpoule`）**：
- 稀有度 Common，`Usage = CombatOnly`（仅战斗中可用），`TargetType = AllEnemies`；
- 效果：**对所有敌人造成 10 点伤害**，伤害为 `ValueProp.Unpowered`（无来源，不吃力量/易伤）；
- 视觉：`NFireSmokePuffVfx` 火焰烟雾。
- 图标可直接复用，不需要新画。

## F. 文案（全缺）

需要中英双语，且键名要按 `<前缀>-<类名>.字段` 生成。设计稿目前是纯中文内部描述，一份可用的本地化表都没有：

| 文档 | 需要的键 |
|---|---|
| `monsters.json` | 4 只怪的 `.name`；每只怪每个招式的 `.moves.<MOVE_ID>.title`（如 `ATTACK_2` / `BUFF_1` / `STUNNED` 等，**ID 大小写敏感**）；可选 `.banter` 战斗内语音 |
| `encounters.json` | `MINTHARA_ELITE.title`（遭遇标题）+ `.loss`（战败文案） |
| `cards.json` | 拾取卡的 `title` / `description` |
| `powers.json` | 「可被拾取」「死亡引爆」「守护灵光」「勇气灵光」的名称与描述 |
| `intents.json` | 仅当你要给灵光做专属意图图标时才需要 |

**注意**：招式的 `MOVE_ID` 是设计稿与代码之间的硬契约（状态机里 `MoveState("ATTACK_2", ...)` 的字符串）。设计稿现在用的是中文描述（"攻击2"），需要先定一套英文 ID 命名。

## I. 技术风险：5 只怪 —— 已降级为"布局调优"，不是引擎上限

> **2026-10-01 修订**：本节初稿写的"原版最多 4 只怪"**是错的**，现已用源码证伪。
> 5 只怪在引擎里完全正常，第一幕原版就有先例。保留结论如下。

### 已证伪：原版没有"4 只上限"

`EncounterModel.Slots` 只是场景里 `Marker2D` 的名字列表，**数量无上限**，且同一场战斗里同时存活的敌人数可以超过它：

| 出处 | 槽位数 | 同时存活敌人 | 镜头 |
|---|---|---|---|
| `PhrogParasiteElite`（**第一幕精英**，Overgrowth/Underdocks 都有） | 5 | `PhrogParasite` 死后由 `InfestedPower.AfterDeath` 召唤 **4 只 `Wriggler`** → **5 只** | `0.95` |
| `OvicopterNormal` | 6（`egg1`~`egg5` + `ovicopter`） | `Ovicopter` + 最多 5 只 `ToughEgg` → **6 只** | `0.8`，`Down*50 + Left*100` |
| `LivingFogNormal` | 6（`bomb1`~`bomb5` + `livingFog`） | `LivingFog` + `BloatAmount` 只 `GasBomb` → **6 只** | `0.9` |
| `FabricatorNormal` | 5（`bot1`~`bot4` + `fabricator`） | `Fabricator` + 动态召唤 | – |

**→ 本设计的 5 只怪（地精近战 + 油桶 + 明萨拉 + 地精远程 + 油桶）落在原版既有实践之内。**

### 因此风险降级为"布局调优项"，而非"能否实现"

仍然存在、但属于进游戏实测微调的问题：

1. **意图框 / 血条是否挤得下** —— 5 个血条里油桶 5 点、明萨拉 150 点，长度差 30 倍。原版有 `MonsterModel.HpBarSizeReduction`（`DecimillipedeSegment` 用 `35f`）可给小怪压血条；
2. **站位宽度** —— 有实测参照可直接抄：5 槽 `TwoTailedRatsNormal` 用 `0.85 / Down*25`，6 槽 `OvicopterNormal` 用 `0.8 / Down*50 + Left*100`；
3. **玩家侧卡牌可视区**是否被挤压（`FullyCenterPlayers` 默认 false，建议保持）；
4. **战斗时长** —— 与"5 只怪"无关，取决于 A1 里"攻击2"的读法（见前文 A1）。

**建议**：直接照 `PhrogParasiteElite` 的场景改一个 5 槽版本（它是同类"1 主怪 + 4 小怪"结构，最贴），进游戏微调坐标即可，不必从零搭。

## 附：review 后建议补充的设计稿结构

把现有内容扩成下面 4 份（对应制作清单的 D1/D2/D3/D4），基本就齐了：

1. **D1 怪物表**（4 行）：名称 / 内部英文名 / 基础血量 / 进阶血量 / 固定或区间 / 受击材质 / 是否可被拾取 / 是否进图鉴；
2. **D2 意图状态机表**（4 行）：每行 `招式ID | 意图类型 | 伤害值×段数 | 施加的 power | 打断后接哪一招`，另附一段自然语言描述状态机走向（含 A3 的 break 语义）；
3. **D3 遭遇编成表**：幕（明确 Overgrowth / Underdocks）/ `RoomType` / `IsWeak` / `Tags` / 槽位名与坐标 / 镜头参数 / `catch` 的技术定义 / 期望出现频率；
4. **D4 数值与进阶曲线**：每只怪的基础值 + 进阶 8 的取值 / 期望回合数 / 期望掉血 / 对标哪一场原版精英。

这 4 份补齐后，剩下的就只是文案、美术、音频三张需求单——那些是"没写"而不是"没定"。
